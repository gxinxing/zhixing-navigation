# 知行 — 岗位任务导航器 Spec

## Why
心智障碍者在支持性就业岗位上因短期记忆弱、步骤多，无法独立完成工作流程，辅导员配比不足（1:5~8）导致无法全程一对一指导。需要一个工具替代辅导员的"逐步提醒"角色，把复杂工作流程变成"跟着做"的图文步骤卡片，让心智障碍者能独立、有序地完成岗位任务。

## What Changes
- 创建 Next.js 14 (App Router) 项目，配置 Tailwind CSS + PWA
- 实现用户端：首页岗位选择、任务列表、步骤卡片（核心）、情绪打卡、求助功能、完成庆祝页
- 实现辅导员端：简易密码登录、数据看板、任务模板编辑器
- 实现语音播报（Web Speech API）、localStorage 数据持久化
- 填充 5 个预置岗位模板（超市理货、咖啡店、图书馆、酒店客房、办公室）
- UI 适配心智障碍者：大字体、大按钮、高对比度、极简界面、强引导

## Impact
- Affected specs: 全新项目，无已有 spec
- Affected code: 全新代码库，从零搭建

## ADDED Requirements

### Requirement: 项目脚手架
系统 SHALL 基于 Next.js 14 (App Router) 创建项目，使用 Tailwind CSS 进行样式开发，配置 PWA 支持离线使用和添加到桌面。

#### Scenario: 项目初始化成功
- **WHEN** 执行项目初始化
- **THEN** Next.js 14 项目创建完成，Tailwind CSS 配置就绪，PWA manifest 配置完成，项目可正常启动

### Requirement: TypeScript 类型定义
系统 SHALL 定义完整的数据类型，包括 JobTemplate、Task、Step、CompletionRecord、MoodRecord、HelpRecord 等接口。

#### Scenario: 类型定义完整
- **WHEN** 项目构建
- **THEN** 所有数据模型类型定义完整，无 TypeScript 编译错误

### Requirement: 预置岗位模板数据
系统 SHALL 提供 5 个预置岗位模板：超市理货员（商品上架10步）、咖啡店助理（制作美式咖啡8步）、图书管理员（图书上架7步）、酒店客房（清洁整理12步）、办公室助理（打印文件6步），每个步骤包含标题、说明、提示。

#### Scenario: 模板数据可加载
- **WHEN** 应用启动
- **THEN** 5 个岗位模板数据可被正确加载和渲染

### Requirement: 首页岗位选择
系统 SHALL 提供首页，展示所有可用岗位卡片（2x2网格），每个卡片包含大图标和岗位名称，底部固定情绪打卡入口。点击岗位卡片进入该岗位的任务列表。

#### Scenario: 用户选择岗位
- **WHEN** 用户在首页点击某个岗位卡片
- **THEN** 导航到该岗位的任务列表页面

### Requirement: 任务列表页
系统 SHALL 展示所选岗位下的所有任务，每个任务卡片包含图标、任务名、步骤数和开始按钮。已完成的任务显示绿色勾和完成时间。底部固定求助按钮。

#### Scenario: 用户查看任务列表
- **WHEN** 用户进入某岗位的任务列表页
- **THEN** 显示该岗位下所有任务卡片，点击"开始"进入步骤卡片页

### Requirement: 步骤卡片（核心功能）
系统 SHALL 每屏只显示一个步骤，包含：进度条、示意图区域（占页面40%）、步骤标题（24px Bold）、步骤说明（18px Regular）、语音重播按钮、"我做完了"大按钮（最小高度56px，满宽）、固定底部求助按钮。进入步骤时自动语音播报，点击"我做完了"显示"做得好！"动画后自动进入下一步。

#### Scenario: 用户逐步完成任务
- **WHEN** 用户进入步骤卡片页
- **THEN** 自动播报当前步骤语音，显示步骤图文内容

#### Scenario: 用户完成一步
- **WHEN** 用户点击"我做完了"
- **THEN** 短暂显示"做得好！"动画，自动进入下一步

#### Scenario: 用户完成全部步骤
- **WHEN** 用户完成最后一步
- **THEN** 显示庆祝页面，包含庆祝动画、任务名称、用时、返回按钮

#### Scenario: 用户重听语音
- **WHEN** 用户点击"再听一遍"
- **THEN** 重新播报当前步骤的语音

### Requirement: 语音播报
系统 SHALL 使用 Web Speech API (SpeechSynthesis) 在进入步骤时自动播报步骤标题和说明，支持手动重播。使用中文语音。

#### Scenario: 语音自动播报
- **WHEN** 用户进入新步骤
- **THEN** 自动播报该步骤的标题和说明文字

### Requirement: 情绪打卡
系统 SHALL 提供5个表情选项（开心、还行、一般、不太好、很难受），单选，工作开始前和结束后各打卡一次。数据存入 localStorage。点击确认后显示"谢谢你的分享！"。

#### Scenario: 用户进行情绪打卡
- **WHEN** 用户选择一个表情并点击确认
- **THEN** 记录情绪数据到 localStorage，显示"谢谢你的分享！"

### Requirement: 求助功能
系统 SHALL 提供求助面板，包含三个选项："这个步骤不懂"（重新播报语音+高亮步骤说明）、"我想重来这一步"（重置当前步骤）、"叫辅导员来"（记录求助事件含任务名+步骤号+时间）。

#### Scenario: 用户请求帮助
- **WHEN** 用户点击"需要帮助"按钮
- **THEN** 弹出求助面板，提供三个求助选项

#### Scenario: 用户选择"叫辅导员来"
- **WHEN** 用户点击"叫辅导员来"
- **THEN** 记录求助事件到 localStorage（含任务名、步骤号、时间戳）

### Requirement: 完成庆祝页
系统 SHALL 在任务全部完成后显示庆祝页面，包含庆祝动画（confetti）、任务名称、完成用时、返回任务列表按钮。

#### Scenario: 任务完成庆祝
- **WHEN** 用户完成所有步骤
- **THEN** 显示庆祝页面，播放 confetti 动画，展示用时信息

### Requirement: 辅导员简易登录
系统 SHALL 提供简易密码登录入口，区分用户端和辅导员端。MVP 阶段使用固定密码。

#### Scenario: 辅导员登录
- **WHEN** 辅导员输入正确密码
- **THEN** 进入辅导员后台首页

### Requirement: 辅导员数据看板
系统 SHALL 展示今日完成次数、求助次数、平均用时等统计数据，学员近况列表（姓名、任务、进度、情绪），情绪趋势（近7天），求助记录列表。

#### Scenario: 辅导员查看数据
- **WHEN** 辅导员进入后台首页
- **THEN** 显示所有学员的完成情况、情绪趋势和求助记录

### Requirement: 任务模板编辑器
系统 SHALL 提供表单式编辑器，支持创建/编辑岗位下的任务流程，包括步骤标题、描述、提示的填写，步骤排序（拖拽调整），预览用户端效果。

#### Scenario: 辅导员编辑模板
- **WHEN** 辅导员在编辑器中修改步骤内容并保存
- **THEN** 模板数据更新到 localStorage，用户端可使用新模板

### Requirement: UI 无障碍适配
系统 SHALL 遵循心智障碍者适配设计：主色 #4F46E5、成功色 #22C55E、警告色 #F59E0B、背景 #F8FAFC；步骤标题24px Bold、步骤说明18px、按钮文字20px Semibold；按钮最小高度56px满宽；卡片内边距24px；进度条8px圆角；按钮按下 scale(0.97)；求助按钮脉冲动画。

#### Scenario: UI 规范一致性
- **WHEN** 检查所有页面
- **THEN** 色彩、字体、间距、交互反馈均符合设计规范

### Requirement: localStorage 数据持久化
系统 SHALL 使用 localStorage 存储所有数据，包括岗位模板、完成记录、情绪打卡记录、求助记录。提供封装好的存取工具函数。

#### Scenario: 数据持久化
- **WHEN** 用户完成任务、打卡情绪或请求帮助
- **THEN** 相关数据正确存入 localStorage，刷新页面后数据仍在

### Requirement: PWA 离线支持
系统 SHALL 配置 PWA manifest 和 Service Worker，支持添加到手机桌面，离线时仍可使用已加载的功能。

#### Scenario: 离线使用
- **WHEN** 用户在无网络环境下打开已安装的 PWA
- **THEN** 应用可正常使用已缓存的页面和功能
